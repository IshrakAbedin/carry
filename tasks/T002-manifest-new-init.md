# T002 — Manifest (CARRY.toml) + `carry new` / `carry init`

Status: pending
Depends on: T001 (CLI scaffold)

## Goal

Implement the `CARRY.toml` manifest model and the project scaffolders, so that
`carry new demo` produces a complete, valid project directory (not yet buildable — the
generated files come in T003, but the scaffold includes placeholder `conanfile.txt` and
`CMakeLists.txt` stubs that T003 will replace with real rendering).

## Context

- Read `DESIGN.md` §3 (project layout), §4 (schema), and `results/T001.md` (module layout as built).
- Add deps with `cargo add`: `serde` (feature `derive`), `toml`, `toml_edit`.
- Work in `src/manifest.rs` (schema + IO) and `src/template.rs` (scaffold file contents).

## Requirements

### manifest.rs
- `#[derive(Serialize, Deserialize)]` types: `Manifest { package: Package, build: Build, dependencies: BTreeMap<String, String> }` with serde defaults so partial TOML parses (defaults: version "0.1.0", type "bin", cpp_std "c++23", c_std "c11"). Use `#[serde(default)]` per field; `dependencies` defaults to empty map.
- `Manifest::load(path) -> anyhow::Result<Self>` and `Manifest::save(&self, path)` — save via `toml_edit` (parse existing doc, set values, write back) so user comments/format survive when T006 edits deps. For now, `save` may start from the parsed existing file if present, else from `toml::to_string_pretty`.
- Validation: `name` must match `[a-z0-9_][a-z0-9_-]*`; `type` ∈ {bin, lib, both}; `version` non-empty. Return `anyhow` errors with `help:` hints.
- `fn conan_ref(pkg: &str, version: &str) -> String` — the mapping from DESIGN.md §4:
  plain → `pkg/ver`, starts with `>` `<` `=` `^` `~` → `pkg/[range]`, empty → `pkg/*`.
- Unit tests (in-file `#[cfg(test)]`): parse a full manifest, parse a minimal one (only
  `[package] name`), round-trip save→load, name validation failures, all `conan_ref` branches.

### template.rs + new/init
- `cmd_new(name, lib: bool)` in `main.rs` (or a `scaffold.rs`-style function set in template.rs):
  - Validate `name` (same rule); refuse to create inside an existing non-empty dir without `CARRY.toml` (error: "dir exists and is not a carry project").
  - Create the layout from DESIGN.md §3: `CARRY.toml` (name/version 0.1.0/type), `.gitignore` (containing `build/`), `src/main.cpp` (hello-world `std::cout`), `include/<name>/<name>.hpp` + `src/lib.cpp` (only if `--lib` or type both — for `new`, `--lib` means type "both"), `tests/test_main.cpp` (trivial assert-based main, exits 0 with "all tests passed" — no framework, per DESIGN §3).
  - Write placeholder `conanfile.txt` (`[generators]\nCMakeDeps\nCMakeToolchain\n`) and a minimal valid `CMakeLists.txt` stub with a comment `# generated by carry — replaced by real render in T003`. (T003 makes these real; placeholders keep the layout visible.)
  - Print the created tree (one file per line) and a "next: cd <name> && carry build" hint.
- `cmd_init()`: same but in cwd; name = current dir name (validated); error if `CARRY.toml` already exists or dir is not a valid name.
- Scaffold templates as `&'static str` consts with `{name}` substitution (simple `replace`, no format! macro tricks on user input).

## Acceptance criteria

- [ ] `cargo test` green, including the new manifest unit tests (paste test summary line).
- [ ] `cargo clippy --all-targets` zero warnings.
- [ ] In a scratch dir: `cargo run -q -- new demo --lib` → tree matches DESIGN §3 exactly; `CARRY.toml` parses; `cat` outputs sensible C++ (compile it once manually with g++ as a sanity check: `g++ -std=c++23 -Iinclude demo/src/lib.cpp demo/src/main.cpp` is NOT expected to work if test_main is included — just compile src files).
- [ ] `carry new demo` again in the same dir → clean error, exit 1.
- [ ] `cd demo && cargo run -q -- init` (from the carry repo) → "already a carry project" error.
- [ ] `carry init` in a fresh empty dir named `good-name` works; in a dir named `Bad Name` it errors on the name rule.
