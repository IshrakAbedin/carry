# carry — Design Document

**carry** is a C/C++ project manager that behaves like Rust's **Cargo**: a single small CLI,
a project manifest, and deterministic build/test/run commands. Under the hood it drives
**CMake** (configuration), **Conan 2** (dependencies), **Ninja** (build), and **g++** (compiler).

This document is the stable reference. **Do not rewrite silently** — architecture changes are
appended to `## Decisions` with a date.

---

## 1. Vision

A C/C++ developer should be able to:

```
carry new myapp          # scaffold
carry add fmt            # add a dependency
carry build --release    # compile
carry run                # build + run
carry test               # build + run tests
carry clean              # wipe build/
```

…without ever touching CMakeLists.txt or conanfile.txt by hand. The manifest (`CARRY.toml`)
is the single source of truth; everything else is generated.

## 2. Command surface (MVP)

| Command | Behavior |
|---|---|
| `carry new <name> [--lib]` | Create `./<name>/` scaffold (bin by default; `--lib` adds a library target) |
| `carry init` | Turn the current dir into a carry project (name from dir; errors if CARRY.toml exists) |
| `carry build [--release]` | Regenerate → conan install → cmake configure → ninja build. Default Debug, `--release` = Release |
| `carry run [args]...` | `build` (Debug) then exec `build/bin/<name> [args]...` |
| `carry test` | `build` (Debug) then `ctest --test-dir build --output-on-failure` |
| `carry clean` | Remove `build/` |
| `carry add <pkg>[@<version>]` | Add/update a dependency in CARRY.toml (toml_edit, preserves formatting) |
| `carry remove <pkg>` | Remove a dependency from CARRY.toml |
| `carry --version`, `--help` | clap-provided |

Non-commands for MVP (future): workspace, publish, lockfile management, custom cmake hooks,
cross-compilation, MSVC/Clang.

## 3. Generated project layout

```
<project>/
├── CARRY.toml          # manifest — user-owned, single source of truth
├── conanfile.txt       # generated by carry
├── CMakeLists.txt      # generated by carry
├── .gitignore          # written by `carry new` (contains build/)
├── src/
│   ├── main.cpp        # if type includes bin
│   └── lib.cpp         # if type includes lib
├── include/<name>/
│   └── <name>.hpp      # if type includes lib
└── tests/
    └── test_main.cpp   # trivial assert-based test binary (no framework), always created
```

Conventions:
- Build dir: `build/` at project root (gitignored). Binaries land in `build/bin/<name>`.
- Library target name: `<name>_lib` (avoids clashing with the executable name).
- Test target: `test_<name>`, registered with CTest as `<name>_tests`.
- Dependency CMake target: `<pkg>::<pkg>` (Conan 2 default); exotic packages needing a custom
  mapping are future work (explicit override key in the manifest).

## 4. CARRY.toml schema

```toml
[package]
name = "demo"          # required; [a-z0-9_][a-z0-9_-]*
version = "0.1.0"      # required; semver string
type = "bin"           # "bin" | "lib" | "both"   (default "bin")

[build]
cpp_std = "c++23"      # default "c++23"
c_std   = "c11"        # default "c11"

[dependencies]
fmt = "10.2.1"         # pkg = version ("10.2.1") or range (">=10")
```

Version mapping to Conan refs:
- plain version `10.2.1` → `fmt/10.2.1`
- range `>=10` → `fmt/[>=10]`
- bare `fmt` (no version) → `fmt/*`

## 6. Build pipeline (`carry build`)

Run from the project root (carry walks up from cwd to find `CARRY.toml`; error if none).

1. Parse `CARRY.toml` → `Manifest` (serde).
2. Render `conanfile.txt` + `CMakeLists.txt`; write if changed.
3. `conan install . --output-folder=build --build=missing -s build_type=<Debug|Release>`
   → writes `build/conan_toolchain.cmake` + CMakeDeps configs into `build/`.
4. `cmake -S . -B build -G Ninja \
      -DCMAKE_TOOLCHAIN_FILE=build/conan_toolchain.cmake \
      -DCMAKE_BUILD_TYPE=<Debug|Release> \
      -DCMAKE_C_COMPILER=gcc -DCMAKE_CXX_COMPILER=g++`
   Always run (reconfigure is cheap; keeps conan updates in sync).
5. `cmake --build build`

`carry test` adds: `ctest --test-dir build --output-on-failure`
`carry run` adds: exec `build/bin/<name> <args...>`, propagating exit code.

Tool invocation rules:
- Stream child stdout/stderr directly to the terminal (never buffer build output).
- On failure: print `error: <tool> failed with exit N` and the command that was run; exit non-zero.
- Missing tool (not on PATH): `error: required tool 'conan' not found on PATH`.
- `--verbose` (global flag): print each command before running it.

- No colors in MVP (plain text, grep-friendly).

## 9. Non-goals (MVP)
