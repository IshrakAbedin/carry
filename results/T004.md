## What was done

- **`src/build.rs`** (was empty scaffold):
  - `run(cmd, args, cwd, verbose) -> Result<()>` — DESIGN §6 tool-invocation rules:
    prints `$ <cmd> <args...>` when verbose; `Command` with inherited
    stdout/stderr (streamed, never buffered) + `current_dir(cwd)` + spawn/wait;
    spawn `ErrorKind::NotFound` → `required tool '<cmd>' not found on PATH`;
    non-zero exit → `<cmd> failed with exit code <n>\n  command: $ <full line>`

    `Manifest::load` → `generate::regenerate` (write-if-changed) →
    `conan install . --output-folder=build --build=missing -s build_type=<Debug|Release>`
    → `cmake -S . -B build -G Ninja -DCMAKE_TOOLCHAIN_FILE=build/conan_toolchain.cmake
    -DCMAKE_BUILD_TYPE=<...> -DCMAKE_C_COMPILER=gcc -DCMAKE_CXX_COMPILER=g++`
    → `cmake --build build`. All in `root`; identical with or without deps
    (conan writes the toolchain file either way — verified).
  - 2 unit tests (hermetic): exact missing-tool message; exact non-zero-exit
    message with command line (via `sh -c "exit 3"`).
- **`src/main.rs`** — `Build` arm now: `find_project_root()` → `build::build()`;

## Key decisions

- **`-s build_type=…` is two argv tokens.** First acceptance run failed with
  conan's `ERROR: 'settings. build_type' doesn't exist for 'settings'`
  (note the space in the name!) because `-s build_type=Debug` was passed as one
  element; conan's `-s` takes the setting as a *separate* argument. The DESIGN
  §6 shell line is two tokens; the bug was in the translation to argv, not in
  the spec. CMake `-DNAME=VALUE` flags are correctly single tokens — only
  conan's `-s` needed splitting.
- **Failure summary names the tool carry spawned** (`cmake`), not the tool that
  failed underneath (ninja/g++). The acceptance text's "g++/ninja failed"
  reading is loose: carry's child is `cmake --build build`, so the summary is
  `error: cmake failed with exit code 1` + `  command: $ cmake --build build`,
  while the g++ diagnostic is streamed live above it. Matches DESIGN §6
  (`error: <tool> failed with exit N`) where `<tool>` is the invoked command.
- **`build()` loads the manifest itself** (caller only has `root`), keeping the
  main.rs dispatch thin per the task note. `prepare_project()` remains for the
  `run`/`test` stubs until T005.
- No "regenerated X" user output — DESIGN §6 doesn't spec it; `regenerate`'s
  changed-flags stay unused (T005+ may use them).
