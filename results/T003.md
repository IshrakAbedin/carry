## Key decisions

- **D9 deviation (found by CMake, recorded per task note):** the §5 example
  `target_link_libraries(test_demo PRIVATE demo fmt::fmt)` **does not
  configure** — CMake 4 rejects linking an EXECUTABLE target into another
  target (`Target "demo" of type EXECUTABLE may not be linked into another
  target`), and `ENABLE_EXPORTS` would not save it anyway (the exe's
  `main` would duplicate the test's). The test target therefore links the
  **library** target (when present) + deps; a bin-only project's test target
  links only deps (no line when empty). Recorded as D9 with a dated note and
  the §5 example line corrected; this is the only place the generator deviates
  from the §5 template text.
- **Zero deps → no `[requires]` header at all** (task-mandated; Conan accepts
  both, empty file stays minimal). `CMakeLists.txt` likewise omits the
  `find_package` block and any empty `target_link_libraries` line rather than
  emitting empty constructs.
- **Sorted `[requires]`:** `dependencies` is a `BTreeMap`, so iteration order
  is already package-name-sorted; no extra sort pass needed (test inserts
  out of order to prove it).
- **Header line version** comes from `env!("CARGO_PKG_VERSION")` (currently
  `0.1.0`), so the "do not edit" banner stays truthful across bumps; goldens
  pin the literal `0.1.0` and will force an update if the crate version moves.
- **§5 inline template comments** (`# one per dependency`, `# only if lib`,
  `# lib first, then deps`) are spec annotations, not literal output — they
  are not emitted into generated files.
- **`find_project_root` error carries no `help:` line** — the acceptance
  criterion quotes the exact message `error: not a carry project (no CARRY.toml
  found)`, so no hint was added (DESIGN §8 says hints only "when obvious").
- `prepare_project()` returns nothing to the user (silent regeneration);
  the `(changed, changed)` tuple is discarded. T004 may want to print
  "regenerated X" lines — the info is already returned by `regenerate`.
