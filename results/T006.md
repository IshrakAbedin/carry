# T006 — `carry add` / `carry remove` (toml_edit, format-preserving) (DONE 2026-09-21)

## What was done

- **`src/manifest.rs`**:
  - `parse_dep_spec(spec) -> Result<(String, String)>` — splits `pkg` / `pkg@version`
    on the **last** `@`; version may be plain (`10.2.1`) or a range (`>=10`); bare
    `pkg` stores an empty version (→ `pkg/*` via `conan_ref`). Name validated with
    the manifest name rule.
  - `Manifest::add_dep(&mut self, path, pkg, version) -> Result<()>` — three cases:
    same version → print `{pkg} already up to date` and **write nothing** (content
    and mtime unchanged); different → replace in place, print
    `updated {pkg} {old} → {new}`; new → print `added {pkg} {version}`. Every write
    goes through the existing `save()` toml_edit round-trip; after a write it prints
    the hint `run: carry build` (it never builds itself).
  - `Manifest::remove_dep(&mut self, path, pkg) -> Result<()>` — removes the key
    (tolerates a `pkg@version` spec, uses the name part), prints `removed {pkg}
    {version}` + the hint; absent → `error: dependency '{pkg}' not found in
    CARRY.toml` (exit 1), file untouched. The now-empty `[dependencies]` table is
    deliberately left in place (stable diff; user may re-add).
  - `validate_name` refactored onto a private labeled helper
    (`validate_labeled_name("project"|"dependency", …)`) so dependency errors read
    `invalid dependency name …` while project errors are unchanged.
  - Empty versions are shown as `(any)` in update/remove messages.
  - 8 new unit tests (20 → 28): spec parsing (incl. last-`@` and bad names),
    add-new (table appended with blank line), add-replace (in place, other deps
    untouched), add-same (content **and** mtime unchanged), add invalid name
    (error + `help:`, file untouched), remove-present (header remains, `pkg@ver`
    tolerated), remove-absent (exact error message, file unchanged), and the
    **formatting-preservation** test asserting the exact raw string after add then
    remove of a manifest with a header comment, an inline comment, and odd
    `c_std   = ` spacing.
- **`src/main.rs`** — `Add`/`Remove` arms wired (find root → parse spec → load
  manifest → `add_dep`/`remove_dep`); the `not_implemented` stub closure deleted;
  `Add` help text corrected from the T001 stub's `fmt/10.2.1` (Conan ref syntax) to
  `fmt@10.2.1` with the range example.

## Key decisions

- **`add_dep`/`remove_dep` take the manifest `path`** (task sketched
  `add_dep(&mut self, pkg, version)`), because the save needs a target and the
  no-write-on-same-version behavior is enforced inside the method. Printing the
  change line + `run: carry build` hint also lives in the method, so main.rs stays
  a 4-line dispatch and the "hint only after a save" rule is local.
- **No manual toml_edit decoration code.** Probes (temp tests, since removed)
  confirmed toml_edit 0.25 handles it: a freshly inserted root table is appended
  with a blank line before it, a new key in an existing table gets a proper
  newline prefix, and `apply_to_doc`/`set_str` (from T002) already preserve
  comments/spacing on existing keys. The task's "append a clean table at the end
  with a blank line before it" requirement is toml_edit's default behavior —
  verified, not engineered.
- **`remove` tolerates `pkg@version`** (strips the version, uses the name) instead
  of erroring: the intent of `carry remove fmt@10.2.1` is unambiguous, and it
  avoids an untested error path.
- **`add` with the same version is a true no-op** — `save()` is skipped entirely
  (not just a byte-identical rewrite), so mtime is preserved; the test asserts
  both content equality and mtime equality.
