# T009 — Demo build with glaze; C++ standard sync (D12) (DONE 2026-09-21)

User-directed ad-hoc task (post-MVP): run a temporary demo project through
carry using **glaze** from Conan Center and fix the C++ version issues.

## What was done

- **Demo** (`/tmp/glazedemo`, temporary — left in place for user inspection,
  safe to delete): `carry new glazedemo` → `carry add glaze` (bare →
  `glaze/[>=0]`, D11) → small `main.cpp` (serialize a struct to JSON, parse
  it back) + a `tests/` round-trip using glaze.
- **Bug found:** the Conan profile's `cppstd` (gnu20) and the generated
  `CMakeLists.txt`'s `CMAKE_CXX_STANDARD 23` had diverged since T004.
  `conan install` failed before compiling anything:

  ```
  ERROR: There are invalid packages:
  glaze/8.3.0: Invalid: Current cppstd (gnu20) is lower than the required C++ standard (23).
  error: conan failed with exit code 6
    command: $ conan install . --output-folder=build --build=missing -s build_type=Debug
  ```

  glaze/8.3.0's recipe *validates* the standard; fmt never checks, which is
  why T004–T008 only ever saw the benign "modified to 23" configure warning.
- **Fix (→ D12):** `conan install` now receives
  `-s compiler.cppstd=<gnuNN>` derived from the manifest's `cpp_std`
  (`c++23` → `gnu23`). Code: `conan_cppstd()` in `src/manifest.rs` (mapping
  + unit test), flag added in `src/build.rs` `build_with`. The profile still
  governs compiler/libcxx/arch; only the standard is overridden (host
  context — unqualified `-s`). Side benefit: the toolchain now emits the
  same standard as the generated CMakeLists, so the "modified to 23"
  warning is gone.
- **Regression guard:** `tests/e2e.rs` gained `glaze_full_loop`
  (`#[ignore]`d per D8, like `fmt_full_loop`): new → bare `add glaze` →
  build → run, asserting the JSON round-trip output.
- **Docs:** DESIGN.md §4 (standard mapping), §6 step 3 (new flag),
  decision D12; README "How it works" paragraph.

## Demo-side notes (glaze 8.3.0 API, not carry bugs)

- Namespace is **`glz`**, not `glaze` (`glaze::` does not exist).
- Entry points are **`glz::write_json(value, buffer)`** and
  **`glz::read_json(value, buffer)`** — value first; the older
  `glz::json_dump` / `glz::read` names do not exist in 8.x.
- glaze is header-only: no link target needed beyond the interface
  `glaze::glaze` (includes only), so the D10 public-link path is
  unexercised by it.

## Open issues

- None. The long-standing benign "gnu20-vs-c++23" configure warning
  (results/T004.md, T008.md) is **gone** as a side effect of D12.
- The `gnu` prefix in the mapping assumes the pinned GCC (D6). When
  MSVC/Clang support lands (DESIGN §10.6) the mapping must be per-compiler
  (MSVC uses bare `17`/`20`/`23` cppstd values).

## Hints for follow-up

- `carry add glaze` (bare) resolves to the **highest available** version
  (8.3.0 at the time of writing). Recipes' standard requirements can jump
  between major versions — the D12 flag makes that a clean conan error
  against the *manifest* standard, which the user can then raise via
  `cpp_std` in CARRY.toml.
- If a future project sets `cpp_std = "c++20"`, glaze/8.3.0 will fail
  validation by design ("required C++ standard (23)") — correct behavior,
  not a carry bug.
- glaze/8.3.0 package is now in the local conan cache (Debug + Release
  irrelevant — header-only, one package), so `glaze_full_loop` is warm.
