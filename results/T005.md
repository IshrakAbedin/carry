# T005 — `carry run`, `carry test` (ctest), `carry clean` (DONE 2026-09-21)

## What was done

- **`src/build.rs`**:
  - Split `build()` into a thin public wrapper (loads the manifest) +
    private `build_with(manifest, root, release, verbose)` so `run_cmd` can
    reuse the pipeline with a single manifest load.
  - `run_cmd(root, manifest, args, verbose)` — DESIGN §2/§6:
    `build_with` (Debug) → check `build/bin/<name>` exists (missing → carry
    error with a `[package].type` hint) → exec the binary with inherited
    stdio (verbose prints `$ <bin> <args...>`). **Child exit code is
    propagated as carry's exit code** via `std::process::exit(code)` — the
    program's own exit, not a carry `error:`; signal death (no code) falls
    back to the DESIGN §8 `101` convention.
  - `test_cmd(root, verbose)` — `build` (Debug) then
    `ctest --test-dir build --output-on-failure` via the shared `run()`
    helper, so ctest failure gets the same tool-failure error format as T004
    (`error: ctest failed with exit code N` + command line), exit 1.
  - `clean_cmd(root)` — `symlink_metadata` on `build/`: absent → prints
    "nothing to clean"; symlink → resolve target (relative resolves against
    the link's dir), refuse if it points **outside** the project
    (`error: refusing to remove … symlink points outside the project`);
    broken symlink → remove the link itself (nothing to destroy); symlink
    inside → `remove_file` the link only (never the target); regular dir →
    `remove_dir_all`. Prints `removed build/` / `removed build/ (symlink)`.
  - 4 new unit tests (tempfile): clean with `build/` (dir gone), without
    (Ok), symlink-outside (error + target and link survive),
    symlink-inside (link gone, target survives).
- **`src/main.rs`** — `Run`/`Test`/`Clean` arms wired (root via
  `find_project_root`; `Run` also loads the manifest for `run_cmd`);
  `prepare_project()` deleted (its work is inside `build()`); `Run` gained a
  `long_about` documenting that **carry flags must come before user args,
  use `--` to separate** (`carry run -- --release`); module doc updated.

## Key decisions

- **Exit-code split.** `carry run` propagates the child's numeric exit code
  (acceptance: `return 3` → exit 3); DESIGN §8's `101` is used only when the
  child was killed by a signal (no code exists to propagate). `carry test`
  does *not* propagate: ctest failure is a carry error (exit 1, tool-failure
  format) per the task requirement "ctest failure → carry error like
  T004's failures".
- **`run_cmd` exits the process directly** (`std::process::exit(code)`)
  rather than encoding the child code in `anyhow` — keeps main.rs's error
  path (`error: …` + exit 1) exclusively for carry's own failures, and
  matches the task spec. Not unit-testable in-process; covered by E2E.
- **Symlink safety in clean.** The refuse-check only fires for live targets
  outside the project; a broken or inside-pointing symlink is safe to
  `remove_file` (the link), which also avoids `remove_dir_all`-following-the
  link entirely.
- **`build()` API unchanged** for `carry build`; `build_with` is the private
  core. `Run` loads the manifest in main.rs (one load, shared with
  `run_cmd`) instead of letting two loads happen.
