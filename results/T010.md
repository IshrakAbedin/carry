# T010 — Compile commands export for editor integration (D13) (DONE 2026-09-21)

## What was done

User-directed post-MVP task: make editors (clangd, VS Code C/C++) work on
carry-managed projects without per-user configuration.

- **`src/build.rs`**:
  - Configure step gains `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON` → CMake writes
    `build/compile_commands.json`.
  - New `pub fn export_compile_commands(root)` — copies
    `build/compile_commands.json` → `<root>/compile_commands.json`,
    write-if-changed (same compare-and-write pattern as
    `generate::write_if_changed`; kept local rather than shared — three
    similar lines beat a premature abstraction). Missing source file is a
    hard error with the path in context (cannot happen with the flag on;
    surfaced loudly if it ever does). Called from `build_with` between
    configure and `cmake --build`, so `run`/`test` export too.
  - `clean_cmd` also removes the root `compile_commands.json` (a stale
    export pointing at a wiped build/ is worse than none); "nothing to
    clean" only when neither `build/` nor the root file exists; a stray
    root file without `build/` is removed alone. Shared helper
    `remove_compile_commands`.
  - 6 new unit tests (hermetic): export copy, write-if-changed (mtime
    equality, same pattern as the generate.rs idempotence test), stale
    update, missing-source error, clean removes root file alongside
    build/, clean removes stray root file without build/.
- **`src/template.rs`** — `GITIGNORE` += `compile_commands.json` (root
  copy is a build artifact; the `build/` copy was already covered by
  `build/`).
- **`src/main.rs`** — `Build` long_about documents the export + clean
  behavior.
- **`tests/e2e.rs`** — hermetic `new_scaffold_layout` asserts the scaffold
  `.gitignore` covers `compile_commands.json`; new `#[ignore]`d
  `compile_commands_export` (D8): `new --lib` → build → root file exists
  with a command entry per scaffold source (`src/lib.cpp`, `src/main.cpp`,
  `tests/test_main.cpp`) → no-change rebuild leaves mtime unchanged →
  `clean` removes it.
- **Docs**: DESIGN.md §2 (build/clean rows), §3 (layout), §6 (configure
  flag + new step 5, build renumbered to 6), decision **D13**; README
  (commands table, conventions, how-it-works); build.rs doc comments
  "steps 1–5" → "1–6".

## Key decisions

- **D13 (in DESIGN.md):** `-DCMAKE_EXPORT_COMPILE_COMMANDS=ON` +
  write-if-changed copy to the **project root**. The root, not `build/`,
  is where editors look by default (clangd walks up from the edited file
  to the source root; VS Code uses the workspace root) — the `build/`
  copy alone would need per-user editor config. Write-if-changed keeps
  the mtime stable on no-op rebuilds so editor file-watchers are not
  triggered. Root file = build artifact → scaffold `.gitignore` covers
  it, `carry clean` removes it.
- **Copy (not symlink)** at the root: consistent with carry's other
  generated-file handling (plain writes, no link edge cases like the
  ones `clean_cmd` already guards for), trivially testable, and the file
  is small (one entry per translation unit).
- **Copy after configure, before build**: even if ninja then fails on a
  translation unit, the editor gets the full, current command list
  (including the failing file) from that configure.
- **No new subcommand**: exporting is a side effect of the build pipeline
  (MVP command surface stays frozen; CMake owns the generation, carry
  only relocates it).
- **e2e assertion anchors on absolute paths**: CMake 4.4.3 + Ninja export
  `"file"` as absolute (e.g. `/…/ccapp/src/main.cpp`), so the test checks
  `"<root>/<rel>"` rather than a bare relative path. Found in the scratch
  run before first test execution.

## Hints for follow-up

- `build/compile_commands.json` (CMake's own copy) still exists after a
  build and is wiped with `build/` by clean — only the root copy is
  carry-managed. Editors using `build/` directly also work.
- If `extra.cmake` (DESIGN §10.2) lands, user CMake appended at the end
  runs after the export flag is set — no interaction expected.
- `CMAKE_CXX_COMPILER_LAUNCHER` / Clang (MSVC/Clang, §10.6) switch the
  export from `"command"` to an `"arguments"` list; nothing in carry
  parses the file, so this is transparent.
